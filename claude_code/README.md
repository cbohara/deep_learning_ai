Interact with CLI -> agentic coding assistant   

Assistant contains
- claude models - opus, sonnet
- memory
- tools

Model will
- gather context ->
- formulate a plan ->
- take an action -> loop

Can be used to 
- discover
    - explore codebase + history
    - search docs
- design
    - plan a project
    - develop tech specs
    - define architecture
- build
    - implement code
    - write + execute tests
    - create commits + PRs
- deploy
    - automate CI/CD
    - configure envs
    - manage deployments
- support + scale
    - debug errors
    - monitor usage + performance

model is given plain text directions ->   
when model responds with a request to use a tool ->   
coding assistant does whatever the tool is supposed to do   

tools include 
- bash - run a shell command
- edit - edit a file
- read - read a file

tool use strength enables claude code to gather context needed
- combine diff tools to handle complex work
- easily navigate codebase 
- can add additional tools to claude code by connecting MCP servers 

`CLAUDE.md`
- how memory is managed across sessions
- define style guide + common commands
- auto loaded into context 
- convo stored locally on machine

## RAG chatbot example
LLM = like an over-enthusiastic person who refuses to stay informed about current events but will answer with absolute confidence   
RAG (retrieval augmented generation) = pull info from up-to-date, trusted data sources to give to the LLM as well -> better responses   

User query from frontend to backend 
1. frontend query submission
- user types query + clicks send
- sendMessage() function
    - disables input and shows loading animation
    - adds user message to chat UI
    - makes POST request to /api/query with JSON payload
2. FastAPI endpoint
- /api/query endpoint receives QueryRequest
- creates a new session ID if not provided 
- calls RAG system
3. RAG system processing
- wraps query - "Answer this question about course materials {query}"
- retrieves convo history if session exists
- calls AI generator with 
    - query prompt
    - convo history
    - available tools
4. AI generator and tool integration
- sends query to claude with system prompt + tools
- if claude decides to use tools
    - execute tool
    - send tool results back to calude
    - gets final response
- returns generated response text
5. vector search
- CourseSearchTool.execute() called by AI with params
- use vector_store.search() with query
- vector store performs 
    - course name resolution via semantic search 
    - returns formatted results 
6. vector store operations
- searches for match
- queries using sentence transformer embeddings
- returns results with docs, metadata, and distances
7. response back to user

vector tangent
- vectorization in deep learning = convert raw data -> numeric vectors to feed into neural network during model training
- vector store = take pre-computed vectors from trained model -> create indices to easily retrieve similar items -> store

types of `CLAUDE.md` files
- `CLAUDE.md`
    - generated by /init
    - commit to git + share
    - in project dir
- `CLAUDE.local.md`
    - not shared
    - personalized
    - in project dir
- `~/.claude/CLAUDE.md`
    - global settings

context

planning mode

- reads thru files
- understand what needs to be implemented 
- iterate

plans are stored in `~/.claude/plans/`   

ollama 
- loads models into memory - LLMs are large, so you need a persistant process managing them rather than cold starting each time
- exposes an API - sends requests to local endpoint localhost:11434
- manages inference - handles tokenization, GPU scheduling, context windows, etc

```
# starts server
ollama serve
# downloads model weights 
ollama pull
# CLI chat wrapper
ollama run
```
